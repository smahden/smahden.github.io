🧩 UIKit

Accessible UI components in plain JavaScript, with no framework, no build step, and no dependencies. Every component below is fully keyboard-operable and announces its state to assistive technology. Try it with Tab and the arrow keys.

Tabs

Arrow keys move between tabs, Home and End jump to the ends, and roving tabindex means one Tab press leaves the whole tablist.

Seven components, about 400 lines of JavaScript, and zero runtime dependencies. Components initialize themselves from data-uikit attributes.

Nothing here needs a mouse: the modal traps and restores focus, the combobox is driven by arrow keys, and every interactive element keeps a visible focus ring.

State is carried by ARIA attributes such as aria-selected, aria-expanded, aria-invalid, and aria-activedescendant, so the component tells assistive tech what it is doing.

Modal dialog

Opens with focus moved inside, traps Tab at both ends, closes on Escape or backdrop click, and returns focus to the button that opened it.

Delete this account?

This is a demo, so nothing will actually happen. Press Escape, or Tab around and notice that focus never leaves this dialog.

Accordion

Each trigger is a real button carrying aria-expanded, and its panel is a labelled region.

Accessibility lives in the DOM and the keyboard model, not in a framework. Building these by hand means understanding focus order, ARIA state, and event handling directly, which transfers to React or anything else.

A Playwright suite drives this page with real key presses and asserts focus position and ARIA state after each one, the behaviour a screen reader would report.

Every color is a custom property. Override the --uikit-* variables, or flip data-theme like the toggle at the top of this page does.

Combobox

Type to filter, arrow keys to highlight, Enter to select, Escape to close. Focus stays in the input; aria-activedescendant points at the highlighted option.

Form validation

Errors are announced through aria-describedby, fields get aria-invalid, and submitting an invalid form moves focus to the first problem.

Toasts

Notifications land in a polite live region, so they are announced without interrupting whatever the user is reading.
